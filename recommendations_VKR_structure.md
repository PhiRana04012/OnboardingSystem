# Рекомендации по структуре и содержанию ВКР

## Требования к ВКР

- **Объём:** ~40 страниц (без приложений)
- **Список источников:** не менее 15 источников
- **Язык:** Русский
- **Формат:** ГОСТ

---

## Рекомендуемая структура ВКР

### 1. ВВЕДЕНИЕ (2-3 страницы)

**Обязательно включить:**

- Актуальность работы (2-3 абзаца)
  - Описать проблему онбординга
  - Привести статистику текучести кадров
  - Показать экономическую целесообразность

- Цель работы (1 абзац)
  - "Разработать веб-приложение для автоматизации и оптимизации процесса онбординга новых сотрудников"

- Задачи (5 пунктов):
  1. Разработать архитектуру и проектировать систему
  2. Реализовать backend с управлением модулями и тестами
  3. Реализовать frontend с интерактивными компонентами
  4. Создать систему отслеживания прогресса и аналитики
  5. Реализовать систему уведомлений, гамификации и интеграций

- Методы исследования
  - Анализ предметной области
  - Проектирование архитектуры
  - Разработка ПО
  - Тестирование

- Практическая значимость
  - Применение в компании
  - Сокращение времени адаптации
  - Улучшение вовлечённости сотрудников

---

### 2. ОБЗОР ПРЕДМЕТНОЙ ОБЛАСТИ (4-5 страниц)

**Разделы:**

2.1. Сущность процесса онбординга
- Определение понятия
- Этапы онбординга
- Роли участников процесса

2.2. Существующие решения на рынке
- Аналоги (назовите 3-4 готовых решения)
- Их преимущества и недостатки
- Почему они не подходят полностью

2.3. Требования к системе
- Функциональные требования (перечислить 10-15)
- Нефункциональные требования (производительность, безопасность, масштабируемость)
- Требования к удобству использования

2.4. Выбор технологий
- Обоснование выбора ASP.NET Core
- Обоснование выбора Vue.js
- Обоснование SQL Server

---

### 3. АНАЛИЗ И ПРОЕКТИРОВАНИЕ СИСТЕМЫ (5-6 страниц)

**Разделы:**

3.1. Архитектура приложения
- Диаграмма компонентов
- Описание слоёв (Presentation, Business Logic, Data Access)
- Объяснение паттернов (MVC, N-tier)

3.2. Модель данных
- ER диаграмма
- Описание основных сущностей (User, Module, Progress, Test, etc.)
- Отношения между сущностями

3.3. API и интерфейсы
- RESTful API endpoints
- Описание основных маршрутов
- Примеры запросов/ответов

3.4. Frontend архитектура
- Компонентная архитектура Vue
- State management с Pinia
- Структура папок

3.5. Безопасность
- JWT аутентификация
- Role-based access control
- Валидация данных

---

### 4. РЕАЛИЗАЦИЯ BACKEND (7-8 страниц)

**Разделы:**

4.1. Настройка проекта
- Инициализация ASP.NET Core проекта
- Настройка зависимостей

4.2. Реализация авторизации
- JWT токены

4.3. Управление модулями обучения

4.4. Система отслеживания прогресса

- Вычисление метрик
- Примеры запросов

4.5. Real-time уведомления

4.6. Интеграции

5.5. Интеграция с API

## Рекомендации по написанию

### Стиль

- ✓ Используйте академический стиль
- ✓ Активный залог (система сохраняет → мы сохраняем)
- ✓ Точные и краткие формулировки
- ✓ Избегайте жаргона без пояснений
- ✓ Нумеруйте все изображения и таблицы

### Структура параграфов

- Каждый параграф должен начинаться с основной идеи
- Поддерживайте идею примерами и доказательствами
- Завершайте параграф выводом

### Цитирование

- Используйте цитаты для подтверждения фактов
- Всегда указывайте источник
- Используйте гарвардский или ГОСТ стиль цитирования

### Формулы и код

```
Для выделения кода используйте:
1. Встроенный код: \`code_here\`
2. Блоки кода: \`\`\`language...код...\`\`\`
3. Нумеруйте листинги: Листинг 4.1
```

## Критерии оценки

**Комиссия обратит внимание на:**

1. **Полнота работы** (90%)
   - Все 5 задач реализованы ✓
   - Документ написан на 90% ✓
   - Тесты пройдены ✓

2. **Качество кода** (80%)
   - Архитектура (слои, паттерны)
   - Читаемость и стиль
   - Обработка ошибок

3. **Документирование** (75%)
   - Комментарии в коде
   - API документация
   - README файлы

4. **Дизайн и UX** (70%)
   - Интуитивный интерфейс
   - Адаптивный дизайн
   - Время загрузки

5. **Безопасность** (80%)
   - Аутентификация/авторизация
   - Валидация данных
   - Защита от common vulnerabilities

## Типичные ошибки, которых нужно избежать

❌ **Не делайте:**
- Копировать весь код в ВКР (только примеры)
- Писать про то, что вы не реализовали
- Забывать про ссылки на источники
- Использовать скриншоты низкого качества
- Писать слишком кратко (менее 30 страниц)
- Забывать про нумерацию слайдов/таблиц

✓ **Делайте:**
- Концентрируйтесь на самостоятельно сделанном
- Объясняйте техническое решение
- Используйте диаграммы и схемы
- Обосновывайте выбор технологий
- Пишите о вызовах и как их решали
- Делайте выводы
